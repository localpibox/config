Automated web application validation using agent-browser, the local vision model (Qwen3.6-35B), and Zod schema validation. Produces structured JSON reports.

## When to Use

When you need to validate a web application's structure, visual appearance, performance, and accessibility. Use when the user asks to "validate a page", "run a browser test", "check web vitals and accessibility", "generate a validation report", or "analyze a URL with vision model".

## Two-Flow Architecture

### Flow A: Bundled Chrome (Default — Automated Testing)

Use for subagents, automated tests, and validation pipelines.

```bash
# Set session isolation
export AGENT_BROWSER_SESSION=$(session-uuid "${PI_WORKTREE_ID}-<test-name>")

# Run commands with bundled Chrome (exec path set in ..env)
agent-browser --session "$AGENT_BROWSER_SESSION" open https://example.com
agent-browser --session "$AGENT_BROWSER_SESSION" snapshot -i
agent-browser --session "$AGENT_BROWSER_SESSION" screenshot --annotate /tmp/ss.png
```

**Properties:**
- Safe, isolated, no host Chrome dependency
- Full cookie/storage/tab isolation via `--session` (verified: different sessions don't share localStorage)
- Uses `AGENT_BROWSER_ALLOWED_DOMAINS` for security (localhost auto-allowed)
- All subagents use this flow
- Executable path configured: `AGENT_BROWSER_EXECUTABLE_PATH=/home/dev/.local/share/agent-browser/chrome/chrome-linux64/chrome`

### Flow B: Host Chrome CDP (Live Interaction — User-Supervised)

Use only for the main agent when the user wants to see the browser in real-time.

```bash
# Connect to host Chrome on port 9222
agent-browser --cdp 9222 open https://example.com
agent-browser --cdp 9222 snapshot -i
```

**Properties:**
- User sees the same browser the agent sees
- Shared state (cookies, storage, tabs)
- Does NOT use `AGENT_BROWSER_ALLOWED_DOMAINS` (conflicts with CDP)
- Only the main agent should use this flow

## Session Naming Convention

```
<worktree-id>-<test-name>-<uuid>
```

- `worktree-id`: cross-worktree uniqueness (from `PI_WORKTREE_ID`)
- `test-name`: human-readable identifier (e.g., `login-flow`, `checkout`)
- `uuid`: prevents collisions (generated by `session-uuid` — installed globally)

```bash
# Generate session ID
session-uuid "${PI_WORKTREE_ID}-login-flow"
# → pi-main-abc123-login-flow-7f3a9b2c
```

## Complete Validation Pipeline

### Step 1: Navigate

```bash
agent-browser --session "$SESSION_ID" open https://example.com
```

### Step 2: Collect Structured Data

```bash
# Web Vitals (Core Web Vitals)
agent-browser --session "$SESSION_ID" vitals --json

# Accessibility (axe-core)
agent-browser --session "$SESSION_ID" a11y --json

# Page Snapshot (interactive elements)
agent-browser --session "$SESSION_ID" snapshot -i

# Annotated Screenshot
agent-browser --session "$SESSION_ID" screenshot --annotate /browser-states/$SESSION_ID/screenshot.png
```

### Step 3: Vision Model Analysis

```bash
# Encode screenshot to base64
SS_BASE64=$(base64 -w 0 /browser-states/$SESSION_ID/screenshot.png)

# Call vision model with structured prompt
curl -s http://127.0.0.1:13305/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d "{
    \"model\": \"Qwen3.6-35B-A3B-MTP-GGUF\",
    \"messages\": [{
      \"role\": \"user\",
      \"content\": [
        {\"type\": \"text\", \"text\": \"<structured prompt with vitals, a11y, snapshot>\"},
        {\"type\": \"image_url\", \"image_url\": {\"url\": \"data:image/png;base64,$SS_BASE64\"}}
      ]
    }],
    \"max_tokens\": 2048
  }"
```

Extract `reasoning_content` first, then `content` fallback:

```bash
python3 -c "
import sys, json
data = json.load(sys.stdin)
msg = data['choices'][0]['message']
reasoning = msg.get('reasoning_content', '')
content = msg.get('content', '')
result = reasoning.strip() if reasoning.strip() else content.strip()
print(result)
"
```

### Step 5: Close Session (prevent zombie processes)

**CRITICAL:** Always close the session when done to prevent Chrome renderer/GPU processes from becoming zombies.

```bash
agent-browser --session "$SESSION_ID" close
```

### Step 6: Validate & Save Report

```bash
# Validate the JSON output against the schema
browser-validate https://example.com --session "$SESSION_ID"

# Report saved to: /browser-states/$SESSION_ID/validated.json
```
```

## Structured Output Utility

The `browser-validate.ts` utility automates the entire pipeline:

```bash
browser-validate https://example.com --session <id> --attempts 3
```

Pipeline steps:
1. Navigate to URL with bundled Chrome
2. Pre-compute vitals, a11y, snapshot, screenshot
3. Encode screenshot to base64
4. Build vision model prompt with schema + pre-computed data
5. Call Lemonade vision model API
6. Clean JSON output (remove markdown fences, preamble)
7. Validate against Zod schema
8. Retry with repair prompt on failure (max 3 attempts)
9. Save report to `/browser-states/<session-id>/validated.json`

## Subagent Orchestration

### Spawn a Subagent for Browser Testing

```javascript
// 1. Generate session ID
const sessionId = execSync(
  `session-uuid "${PI_WORKTREE_ID}-test-name"`
).toString().trim();

// 2. Load prompt template
const prompt = readFileSync(`${process.env.PI_SUPPORT_DIR || '/opt/pi-support'}/config/subagent-browser-prompt.txt`, "utf-8");

// 3. Spawn subagent
const result = await subagent({
  agent: "researcher",
  task: `${prompt}\n\nRun test on: https://example.com\nSession: ${sessionId}`,
  outputSchema: JSON.parse(
    readFileSync(`${process.env.PI_SUPPORT_DIR || '/opt/pi-support'}/schemas/subagent-browser-schema.json`)),
});

// 4. Validate output
const validated = await validateSubagentOutput(result);
if (!validated.success) {
  // Retry with repair prompt (max 2 retries)
  const repairPrompt = buildRepairPrompt(validated.error, result);
  const retry = await subagent({ agent: "researcher", task: repairPrompt });
  // Validate again...
}
```

### Key Rules

- **Always use bundled Chrome** for subagents (not CDP)
- **Always set unique `AGENT_BROWSER_SESSION`** per subagent
- **Always pass JSON schema** in the prompt
- **Always validate** the output on the parent side
- **Always retry** on validation failure (max 3 attempts total)
- **Cap at 8 concurrent** browser contexts per Chrome instance

## State File Management

### Storage

```
/browser-states/
  ├── <session-id>/
  │   ├── state.json          (cookies + localStorage)
  │   ├── screenshot.png      (annotated screenshot)
  │   └── validated.json      (validation report)
  └── ...
```

### Housekeeping

Automatic cleanup on container start (`.scripts/post-start.sh`):
- Remove sessions older than 7 days
- Keep only 20 most recent sessions

Manual cleanup:
```bash
browser-state-cleanup
```

### Save/Load State

```bash
# Save current session state
agent-browser --session "$SESSION_ID" state save /browser-states/$SESSION_ID/state.json

# Load previous state (for logged-in user testing)
agent-browser --session "$SESSION_ID" state load /browser-states/$SESSION_ID/state.json
```

## Pitfalls

- **Chrome must be available** — bundled Chrome is installed via `agent-browser install` and configured via `AGENT_BROWSER_EXECUTABLE_PATH`
- **Chrome process cleanup** — always close sessions with `agent-browser --session <id> close` to avoid zombie processes; `browser-state-cleanup` kills orphans on container start
- **Large base64 payloads** — use JPEG quality 50-60 to keep under 500KB
- **Vision model truncation** — use `max_tokens: 2048` minimum
- **Session isolation** — never reuse session IDs across tests
- **CDP conflicts** — CDP mode does NOT use `AGENT_BROWSER_ALLOWED_DOMAINS`
- **Context limit** — cap at 8 concurrent browser contexts

## Verification

- Session isolation: two sessions with different IDs don't share cookies
- State persistence: `--state save` / `--state load` preserves cookies
- Housekeeping: cleanup runs on container start, keeps ≤20 sessions
- Structured output: `browser-validate` produces valid JSON reports
- Repair loop: invalid JSON triggers retry with error message
- Subagent validation: `validate-subagent-output` validates and retries
